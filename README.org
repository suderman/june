#+TITLE: June

June is Jon's personal assistant: one persistent daemon on Pi Durable that he talks to from Kitty and Telegram. She reads Org for tasks and knowledge and Herdr for live agent sessions. She does not replace either, and she has no shell. Design and rationale are in [[file:docs/architecture.org][docs/architecture.org]].

* Commands

#+begin_src sh
june                 # terminal client attached to the primary conversation
june ask "What are my agents doing?"
june ask --json "..."    # {"requestId","status","text","reason"}
echo "..." | june ask -
june status [--json] # daemon, model, and conversation state; no model call
june doctor          # configuration and dependency checks
june serve           # the daemon
#+end_src

Exit codes: 0 answered, 1 unanswered or failed, 2 usage, 3 daemon not running. In the client, Enter sends (as a steer while June is working), Alt+Enter queues a follow-up, Esc runs =/stop=, Ctrl+D detaches.

The terminal client, =june ask=, and Telegram share the same slash commands, with the same meanings and replies:

| Command                  | Effect                                                         |
|--------------------------+----------------------------------------------------------------|
| =/new=                   | Stop the run, drop queued messages, start a fresh context. History stays in storage. |
| =/stop=                  | Stop the current run; queued messages continue.                |
| =/compact [instructions]= | Compact the context now.                                      |
| =/status=                | Model, state, queue, context use, and spend.                   |
| =/help=                  | List the commands.                                             |

There is one conversation, so =/new= and =/compact= from any surface affect all of them. Command replies are not part of the conversation; in the terminal they disappear on reconnect, as Telegram's replies sit only in the chat. Detaching or losing the connection never stops work, and the client reconnects by itself. From another host, run =ssh -t kit june= or =ssh kit june ask "..."=.

* Files

This repository holds code only. June reads configuration and identity in place from the directories in =JUNE_CONFIG_PATH=, colon-separated, least specific first. Without it she reads only =$XDG_CONFIG_HOME/june/=. Jon's NixOS module sets three layers:

| Layer     | Directory                 | Kept in                  | Holds                                         |
|-----------+---------------------------+--------------------------+-----------------------------------------------|
| Harness   | =~/.agents/june/=          | Git (suderman/agents)    | =config.json= defaults, =AGENTS.md= conventions |
| Personal  | =~/profile/june/=          | Syncthing                | =SOUL.md=, =config.json= with =daemonHost=       |
| Machine   | =$XDG_CONFIG_HOME/june/=   | this host only           | optional =config.json= overrides                |

=config.json= files merge in path order: objects key by key, arrays and values replaced. =SOUL.md= and =AGENTS.md= come from the most specific directory that has them. Skill directories are configuration too (=skillDirs=); none are built in.

Runtime files stay on the daemon host and are never synced:

| What                 | Where                                |
|----------------------+--------------------------------------|
| Durable state        | =$XDG_STATE_HOME/june/june.sqlite=    |
| Telegram attachments | =$XDG_STATE_HOME/june/files/inbox/=   |
| Socket               | =$XDG_RUNTIME_DIR/june/june.sock=     |

=JUNE_STATE_DIR=, =JUNE_RUNTIME_DIR=, and =JUNE_SOCKET= override these, which is how a development daemon runs beside the real one. Never put the state directory in Syncthing: copying a live SQLite database with its WAL corrupts it.

* Configuration

Keys, with the defaults that apply when no layer sets them:

#+begin_src json
{
  "model": { "provider": "(required)", "modelId": "(required)", "thinkingLevel": "medium" },
  "providersFile": "~/.pi/agent/models.json",
  "envFiles": [],
  "contextCap": 200000,
  "daemonHost": null,
  "skillDirs": [],
  "org": { "root": "~/org" },
  "dispatch": { "hosts": [] },
  "herdr": { "session": "default", "host": "<hostname>", "hosts": {}, "allowPrompt": false },
  "telegram": { "tokenEnv": "JUNE_TELEGRAM_BOT_TOKEN", "allowedUserIds": [] }
}
#+end_src

- =model.provider= names a provider in =providersFile=, Pi's own =models.json=. Its =apiKey= must be a =$VARIABLE=.
- =envFiles= are dotenv files read for keys at startup, for development. The service gets keys from its =EnvironmentFile=.
- =daemonHost= is the machine that runs June. Keep it in a layer every host has, such as a synced one. On any other machine, =june=, =june ask=, and =june status= run there over SSH when no local daemon answers. =JUNE_LOCAL=1= disables that.
- =skillDirs= are read in place; =skill_read= only reads inside a listed skill's directory.
- =herdr.hosts= lists other machines June may inspect read-only over SSH, such as ={"cog": {}, "lux": {}}=; ={"ssh": "target"}= overrides the SSH destination.
- =dispatch.hosts= are the machines June may queue AUTO tasks for; the first is the default. Empty, the default, leaves out =org_queue_task= and =org_dispatch_now=.
- =herdr.allowPrompt= enables =herdr_prompt_agent=, which types a follow-up into an existing agent on this host.
- =telegram= turns the channel on. Leave it out to run without Telegram. The allowed user id is personal, so it belongs in =~/profile/june/config.json=.

* Telegram setup

1. Create a new bot with @BotFather. Do not reuse the Hermes bot: two processes polling one token fail with 409 Conflict.
2. Put =JUNE_TELEGRAM_BOT_TOKEN=<token>= in an agenix secret, or an env file for development.
3. Find Jon's numeric user id (for example from @userinfobot) and set ="telegram": {"allowedUserIds": [<id>]}=.
4. Restart June. =june status= shows =telegram polling=, and a message to the bot appears in the terminal client too.

Only allowed users reach the model. Private chats share the primary conversation; Telegram's =/new= resets it for every surface.

* Development

#+begin_src sh
nix develop           # node 22 and ripgrep
npm ci
npm run typecheck
npm test              # also: nix flake check
JUNE_STATE_DIR=/tmp/june-dev JUNE_RUNTIME_DIR=$XDG_RUNTIME_DIR/june-dev bin/june serve
JUNE_STATE_DIR=/tmp/june-dev JUNE_RUNTIME_DIR=$XDG_RUNTIME_DIR/june-dev bin/june
#+end_src

On kit, the =june= command from Jon's NixOS module runs this checkout instead of the pinned package whenever =src/cli.ts= and =node_modules= exist here, the service included. Edit, then =systemctl --user restart june= for daemon changes, or rerun the client; =june status= shows the code path in use. =JUNE_SOURCE=none= forces the package, and =JUNE_SOURCE=<dir>= picks another checkout. Remove =node_modules= or set =JUNE_SOURCE=none= in the service before leaving a half-finished change, since a daemon that cannot start leaves June down. Configuration, =SOUL.md=, =AGENTS.md=, and skills are read live in either case.

Unix socket paths are limited to 108 bytes, so keep =JUNE_RUNTIME_DIR= short. Tests use pi-ai's faux model and a fake Telegram port; they never call a provider or Telegram. =nix build= typechecks and produces =result/bin/june=. After changing dependencies, update =npmDepsHash= in =nix/package.nix=.

* Deployment

The flake exports =packages.<system>.default=. The Home Manager module lives in [[https://github.com/suderman/nixos][suderman/nixos]] as =programs.june=, following that repository's conventions: =programs.june.enable= puts =june= on PATH, and =programs.june.daemon.enable= on kit runs =june serve= as a user service, persists =~/.local/state/june=, and reads provider keys from Pi's agenix-generated =~/.pi/agent/.env=. Logs go to the journal as =level event key=value= lines with secrets redacted: =journalctl --user -u june=. June and the Hermes June can run side by side until Jon cuts over.

* Roadmap

Short technical list until this moves into the Org project.

1. Telegram with a real bot token on kit.
2. Safe Org writes through =org-edit=: capture to the inbox, add a note to a task, change state, schedule. Idempotency keys, a check of the current state before retrying, and refusal of =asana.org= and conflict copies.
3. Herdr follow-up prompts on by default once tested, with a confirmation rule for agents that are blocked on an approval.
4. A bounded supervision check from a systemd timer: deterministic Herdr and Org scans, silence when nothing changed, a small ledger of notified and acknowledged events, and a separate background conversation for judgment.
5. Upgrade to Pi Durable 1.4 when pi-durable-telegram does.
6. Later: notmuch, calendar, Home Assistant, voice.
