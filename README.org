#+TITLE: June

June is a personal assistant: one persistent daemon on Pi Durable that the user talks to from a terminal and Telegram. She reads Org for tasks and knowledge and Herdr for live agent sessions, does quick checks and small edits herself with a shell and file tools, and hands larger work to coding agents through an Org dispatcher. Design notes are in [[file:docs/architecture.org][docs/architecture.org]].

* Built on

- [[https://github.com/earendil-works/pi/tree/main/packages/durable][Pi Durable]]: the harness June runs in. Her conversation, tasks, tools, and compaction are durable, so a restart resumes work rather than losing or repeating it. [[https://github.com/earendil-works/pi/tree/main/packages/ai][pi-ai]] talks to the models and [[https://github.com/earendil-works/pi/tree/main/packages/tui][pi-tui]] draws the terminal client.
- [[https://github.com/smixs/pi-durable-telegram][pi-durable-telegram]]: the Telegram channel for Pi Durable.
- [[https://github.com/earendil-works/pi/tree/main/packages/coding-agent][Pi Coding Agent]]: the coding agent the dispatcher starts for AUTO tasks. June reads her providers from its =models.json=.
- [[https://herdr.dev][Herdr]]: the runtime those agents run in, one pane each. June reads their status through its CLI.
- [[https://orgmode.org][Org]] in [[https://www.gnu.org/software/emacs/][Emacs]]: where tasks, projects, calendars, and June's own files live. Task states and dates are set by Org itself, through Emacs in batch.
- [[https://github.com/BurntSushi/ripgrep][ripgrep]]: how June searches Org.

* Commands

#+begin_src sh
june                 # terminal client attached to the primary conversation
june ask "What are my agents doing?"
june ask --json "..."    # {"requestId","status","text","reason"}
echo "..." | june ask -
june status [--json] # daemon, model, and conversation state; no model call
june doctor          # configuration and dependency checks
june init [NAME]     # copy the starting files into place
june serve           # the daemon
#+end_src

Exit codes: 0 answered, 1 unanswered or failed, 2 usage, 3 daemon not running. In the client, Enter sends (as a steer while June is working), Alt+Enter queues a follow-up, Esc runs =/stop=, Ctrl+D detaches.

The terminal client, =june ask=, and Telegram share these slash commands:

| Command                   | Effect                                                                                 |
|---------------------------+----------------------------------------------------------------------------------------|
| =/new=                    | Stop the run, drop queued messages, start a fresh context. History stays in storage. |
| =/stop=                   | Stop the current run; queued messages continue.                                        |
| =/compact [instructions]= | Compact the context now.                                                               |
| =/status=                 | Model, state, queue, context use, and spend.                                           |
| =/help=                   | List the commands.                                                                     |

The terminal client and =june ask= also support =/reload=, which rescans the skill directories and rereads =SOUL.org=, =MEMORY.org=, and =AGENTS.md= without a model call or restart. Code, =config.json=, provider, and environment changes need a daemon restart.

There is one conversation, so =/new= and =/compact= from any surface affect all of them. Detaching or losing the connection never stops work, and the client reconnects by itself. From another machine, =june= runs on the daemon host over SSH (see =JUNE_DAEMON_HOST=).

* Files

The repository holds code and templates only. June keeps her files in three XDG directories, each overridable:

| What   | Directory (override)                         | Holds                                                |
|--------+----------------------------------------------+------------------------------------------------------|
| Config | =$XDG_CONFIG_HOME/june/= (=JUNE_CONFIG_DIR=) | =config.json=, =AGENTS.md=                           |
| Data   | =$XDG_DATA_HOME/june/= (=JUNE_DATA_DIR=)     | =SOUL.org=, =MEMORY.org=, =HEARTBEAT.org=, =JOURNAL.org= |
| State  | =$XDG_STATE_HOME/june/= (=JUNE_STATE_DIR=)   | the database, attachments, receipts, reflection copies |

The socket is =$XDG_RUNTIME_DIR/june/june.sock= (=JUNE_RUNTIME_DIR=, =JUNE_SOCKET=). Keep the state directory out of any sync tool: copying a live SQLite database with its WAL corrupts it. The data directory may be a link to a synced folder.

Machine settings come from the environment: =JUNE_DAEMON_HOST= (the machine that runs June) and =TELEGRAM_ALLOWED_USERS= (comma-separated ids; Telegram is off without it). A =config.json= that sets =daemonHost= or =telegram= is refused.

=templates/= holds starting points that name nobody: =SOUL.org= (her role, judgment, and voice, with a character section to write), =MEMORY.org= and =HEARTBEAT.org= (their shape, with placeholders), and an example =config.json=. ={{name}}= stands for the user. =june init [NAME]= copies whichever are missing into the data and config directories with the name filled in, taking =user.name= from =config.json= when no name is given, and never overwrites a file. June has no identity until =SOUL.org= exists; she creates =MEMORY.org= and =JOURNAL.org= when she first writes to them.

* Configuration

Keys of =config.json=, with their defaults:

#+begin_src json
{
  "user": { "name": null },
  "model": {
    "chat": { "provider": "(required)", "modelId": "(required)", "thinkingLevel": "medium" },
    "focus": null,
    "patter": null
  },
  "providersFile": "~/.pi/agent/models.json",
  "envFiles": [],
  "contextCap": 200000,
  "skillDirs": [],
  "org": { "root": "~/org", "people": "~/org/people.org" },
  "dispatch": { "hosts": [] },
  "herdr": { "session": "default", "host": "<hostname>", "hosts": {}, "allowPrompt": false },
  "rhythm": { "wake": "05:00", "quiet": "22:00", "sleep": "01:00" },
  "reflection": { "enabled": true, "quietMinutes": 60, "recentDays": 3, "periods": ["week", "month", "quarter", "year"] },
  "heartbeat": { "enabled": false, "everyMinutes": 60, "chattingMinutes": 15 },
  "mail": { "enabled": false, "query": "tag:inbox and tag:unread", "accounts": {} },
  "patter": { "openAfterSeconds": 8, "gapsSeconds": [25, 25, 25, 40, 60, 90, 120, 180] },
  "situation": { "calendars": [], "homeAssistant": { "people": [], "weather": null, "pollSeconds": 300 } }
}
#+end_src

- =user.name= is the person June serves. Her prompts and tools use it; without it she says "the user".
- =model.chat= is June's everyday model. Its =provider= names a provider in =providersFile=, Pi's =models.json=, whose =apiKey= must be a =$VARIABLE=.
- =model.focus= is the model for careful work, such as ={"modelId": "gpt-6.1-sol"}=; =provider= and =thinkingLevel= default to chat's. Without it there is no =focus= tool.
- =model.patter= is a cheap model for company during long waits; =provider= comes from chat. Without it there is no patter.
- =envFiles= are dotenv files read for keys at startup, for development. A service should get keys from its environment.
- =skillDirs= are read in place; =skill_read= only reads inside a listed skill's directory.
- =herdr.hosts= lists other machines June may inspect read-only over SSH, such as ={"laptop": {}}=; ={"ssh": "target"}= overrides the destination. =herdr.allowPrompt= enables =herdr_prompt_agent=, which types a follow-up into an agent on this host.
- =dispatch.hosts= are the machines June may queue AUTO tasks for; the first is the default. Empty leaves out the task-writing tools.
- =rhythm= is the user's day in local =HH:MM=: heartbeats run from =wake= until =quiet=, and the nightly reflection from =sleep= until =wake=.
- =reflection= runs the nightly pass once the user has been quiet for =quietMinutes=; =recentDays= is how many recent "Day's end" entries June sees in her prompt; =periods= are the longer digests that follow it.
- =heartbeat= enables a private look every =everyMinutes= in waking hours; the user counts as chatting if they wrote within =chattingMinutes=.
- =mail= gives each heartbeat the new mail matching =query= in notmuch since the last look; =accounts= names each top-level maildir folder, such as ={"personal": "home"}=.
- =situation= feeds the =now= section: =calendars= are Org files read for today and tomorrow, =homeAssistant.people= are =person.*= entities, =homeAssistant.weather= a =weather.*= entity, polled every =pollSeconds= when =HASS_URL= and =HASS_TOKEN= are set.
- =patter= sets when patter speaks: a run busy =openAfterSeconds= becomes a wait, and =gapsSeconds= are the pauses between lines, the last repeating.

* What June does

** The moment

June's prompt ends with a =now= section: the weekday, the rough hour, when the sun next sets or rises, today's and tomorrow's weather, today's and tomorrow's calendar entries, and which zone each configured person is in. She uses it to judge, not to narrate. Home Assistant is polled in the background, so a reply never waits on it, and lines it cannot fill are left out. The section changes about once an hour, so the prompt cache mostly holds; the =clock= tool gives the exact time.

** Heartbeat

Every =heartbeat.everyMinutes= between =wake= and =quiet=, June takes a private look at the moment in the main conversation, with her standing instructions from =HEARTBEAT.org=, what changed in her =now= section since the last look, and whether the user is chatting. She answers =QUIET= or a message. The user never sees the look itself: the terminal hides its input, tools, and quiet answers, and Telegram gets only a real message. A heartbeat waits while June is busy, and a receipt in the state directory keeps a restart from repeating one. June updates =HEARTBEAT.org= when told what to watch for.

With =mail= on, each look also lists the mail that arrived since the last one, sorted before June sees it. Messages from people come first, marked when the user has written to them before; automated senders (no-reply and alert addresses, mail domains such as =updates.=, auto-replies) follow in one line each; newsletters and list mail (=List-Unsubscribe=, =List-Id=, bulk =Precedence=) are only counted; the user's own messages are left out. She sees senders and subjects only, framed as outside text, and reads a message with notmuch when it may matter.

** Shell and files

June has Pi Durable's =bash=, =read=, =edit=, and =write= tools, running on the daemon host as the user. Commands stop after 120 seconds unless given a longer =timeout=, and =/stop= kills them. A call interrupted by a restart comes back as interrupted rather than running again. =edit= fails when the text it replaces has changed. The tools grant capability; =AGENTS.md= sets what she does herself and what needs approval.

** Chat, focus, work, and patter

- Chat (=model.chat=) is everyday talk. Focus (=model.focus=) is careful work; the =focus= tool switches to it and back, and a restart or =/new= starts relaxed.
- =work= hands a self-contained brief to a background child conversation with her tools and identity. The call returns at once, so the user can keep talking; only the final report comes back, as a =[work]= follow-up. A restart resumes the same brief without running it twice.
- Patter (=model.patter=) keeps the user company during a long wait with short playful lines that never claim results or promise anything. Lines are display-only: no model context, compaction, or memory review contains them. On Telegram one message grows by edits, so the phone buzzes once per wait.

** Memory and journal

- =SOUL.org= is June's identity.
- =MEMORY.org= is a page or two of lasting facts about the user's life and how to work with them. June updates it when told something lasting, and compaction and the nightly reflection review it.
- =JOURNAL.org= is June's own dated journal, written with the =journal= tool and read on demand. It is not in her prompt, apart from the last few "Day's end" entries and the latest week's and month's digests.
- =org.people= (=~/org/people.org= by default) is the user's rolodex, which June keeps: one heading per person (pets the household cares about included) with =:WHO:= (who they are to the user), =:EMAIL:=, =:PHONE:=, =:ADDRESS:=, and =:BIRTHDAY:= properties and dated notes. She adds people as they come up in conversation, mail, and Org, and puts contact details in the address book too, which she reads and edits with khard. The heartbeat's mail list names senders from both, and a sender either one knows by name counts as a person.
- Each night, in the sleep hours, once the user has gone quiet, one request rewrites the day just gone with the whole day in view, closes it with a "Day's end" entry, and carries lasting facts into =MEMORY.org=. The replaced text is kept under =reflection/= in the state directory.
- On the last day of a week (Sunday), month, quarter, or year, a longer pass follows the nightly one and writes a digest: "Week's end" under the Sunday, "Month's end" and "Quarter's end" under the month, "Year's end" under the year. A week reads its days in full, a month its days' endings and weeks, and a quarter or year its months' digests. A night that is missed catches up on the next one.
- Before compaction, one request produces the working summary and a memory review. A failed review or save skips compaction and keeps the old context. Saves are atomic renames checked against the reviewed text and refuse Syncthing conflict copies; this is not a cross-host lock.

** Org tasks

June reads Org with ripgrep and writes only through =org-edit= and the dispatcher. With =dispatch.hosts= set she can:

- find or create a project file under =~/org/work= (=org_projects=, =org_create_project=);
- queue a new AUTO task and nudge the dispatcher (=org_queue_task=, =org_dispatch_now=), then follow it and report its transitions;
- resume an existing TODO, EVAL, or HOLD task when the user asks (=org_resume_task=);
- close a task she created once its result is reviewed (=org_complete_task=).

She never writes =asana.org=, =inbox.org=, archives, or conflict copies. The dispatcher, =org-edit=, =herdr-link=, their prompts, and the =project-org-tasks= and =org-triage= skills live in =org/= and =skills/=; see [[file:org/README.org][org/README.org]].

* Telegram setup

1. Create a bot with @BotFather. Two processes polling one token fail with 409 Conflict.
2. Put =TELEGRAM_BOT_TOKEN=<token>= in the service environment, or an env file for development.
3. Set =TELEGRAM_ALLOWED_USERS= to the user's numeric id.
4. Restart June. =june status= shows =telegram polling=.

Only allowed users reach the model, and private chats share the primary conversation. What June says on her own initiative, such as a =[work]= report, a =[follow]= update, or a heartbeat message, goes where the user last spoke to her. She answers the terminal in Org markup and Telegram in Markdown.

* Development

#+begin_src sh
nix develop           # node 22 and ripgrep
npm ci
npm run typecheck
npm test              # also: nix flake check
org/tests/test-org-dispatch && org/tests/test-org-edit
JUNE_STATE_DIR=/tmp/june-dev JUNE_RUNTIME_DIR=$XDG_RUNTIME_DIR/june-dev bin/june serve
JUNE_STATE_DIR=/tmp/june-dev JUNE_RUNTIME_DIR=$XDG_RUNTIME_DIR/june-dev bin/june
#+end_src

Tests use pi-ai's faux model and a fake Telegram port, never a real provider. Unix socket paths are limited to 108 bytes, so keep =JUNE_RUNTIME_DIR= short. =nix build= typechecks and produces =result/bin/june=. After changing dependencies, update =npmDepsHash= in =nix/package.nix=.

* Deployment

The flake exports =packages.<system>.default=. Logs go to stdout and stderr as =level event key=value= lines with secrets redacted. A Home Manager module that runs =june serve= as a user service, with its keys and the dispatcher timer, is =programs.june= in [[https://github.com/suderman/nixos][suderman/nixos]]. Its =june= wrapper runs a local checkout instead of the package when one with =node_modules= is present (=JUNE_SOURCE=none= forces the package), and =june status= shows which is in use.
