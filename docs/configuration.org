#+TITLE: Configuring June

* Files
The repository holds code and templates only. June keeps her files in three XDG directories, each overridable:

| What   | Directory (override)                         | Holds                                                |
|--------+----------------------------------------------+------------------------------------------------------|
| Config | =$XDG_CONFIG_HOME/june/= (=JUNE_CONFIG_DIR=) | =config.json=, =AGENTS.md=                           |
| Data   | =$XDG_DATA_HOME/june/= (=JUNE_DATA_DIR=)     | =SOUL.org=, =MEMORY.org=, =HEARTBEAT.org=, =JOURNAL.org=, =MOOD.org=, =SELF.org= |
| State  | =$XDG_STATE_HOME/june/= (=JUNE_STATE_DIR=)   | the database, =inbox/=, receipts, reflection copies |

Files sent to June land in =inbox/YYYY-MM-DD/HHMM-<name>= in the state directory, private to the user, and are deleted after 30 days. The inbox is a landing place, not storage: June copies what is worth keeping into the right Org task directory.

The socket is =$XDG_RUNTIME_DIR/june/june.sock= (=JUNE_RUNTIME_DIR=, =JUNE_SOCKET=). Keep the state directory out of any sync tool: copying a live SQLite database with its WAL corrupts it. The data directory may be a link to a synced folder.

Machine settings come from the environment: =JUNE_DAEMON_HOST= (the machine that runs June). A =config.json= that sets =daemonHost= is refused. Telegram's settings are environment too: =TELEGRAM_BOT_TOKEN= and =TELEGRAM_ALLOWED_USERS=; a =telegram= block in =config.json= is ignored.

=templates/= holds starting points that name nobody: =SOUL.org= (her role, judgment, and voice, with a character section to write), =MEMORY.org= and =HEARTBEAT.org= (their shape, with placeholders), an example =config.json=, and a starter =AGENTS.md= of the conventions June works by: Org as the authority, task states and AUTO, what needs approval, keeping credentials out of answers, and where tasks go. ={{name}}= stands for the user and ={{org}}= for =org.root= in =config.json=, which =june init= places first. Without an =AGENTS.md=, June is told she has none of the user's conventions and to ask before anything destructive, external, or outside the request. =avatar/= is the base avatar set of labelled placeholders, used in place; =june init= does not copy it. =june init [NAME]= copies whichever are missing into the data and config directories with the name filled in, taking =user.name= from =config.json= when no name is given, and never overwrites a file. June has no identity until =SOUL.org= exists; she creates =MEMORY.org= and =JOURNAL.org= when she first writes to them.

- =user.name= is the person June serves. Her prompts and tools use it; without it she says "the user".
- =model.chat= is June's everyday model. Its =provider= names a provider in =providersFile=, Pi's =models.json=, whose =apiKey= must be a =$VARIABLE=.
- =model.focus= is the model for careful work, such as ={"modelId": "gpt-6.1-sol"}=; =provider= and =thinkingLevel= default to chat's. Without it there is no =focus= tool.
- =model.patter= is a cheap model for company during long waits; =provider= comes from chat. Without it there is no patter.
- =envFiles= are dotenv files read for keys at startup, for development. A service should get keys from its environment.
- =skillDirs= are read in place; =skill_read= only reads inside a listed skill's directory.
- =org.agendaFiles= is the list of agenda files the dispatcher maintains, which June reads to find tasks.
- =herdr.hosts= lists other machines June may inspect read-only over SSH, such as ={"laptop": {}}=; ={"ssh": "target"}= overrides the destination. =herdr.allowPrompt= defaults to true; false removes =herdr_prompt_agent=.
- =dispatch.hosts= are the machines June may queue AUTO tasks for. Empty leaves out the task-writing tools. =dispatch.host= (the first of =hosts= by default) and =dispatch.agent= (pi by default) are what the dispatcher writes into an AUTO task's drawer when it has no =HOST= or =AGENT= and no tag names one; June's own tasks use them too. =dispatch.agents= are the agents June may choose for a task she queues or resumes (just =dispatch.agent= without it); each must be one the dispatcher can launch. To let her pick Claude Code, list it, such as =["pi", "claude"]=. =dispatch.improve= turns on =june_improve=: =file= is the Org file, under =org.root=, that its tasks go in, usually June's own project file, whose first repository should be her checkout; =agent= and =host= default to =dispatch.agent= and =dispatch.host=. =dispatch.settle= is how many seconds a heading the user typed must stay unchanged before the dispatcher launches it (120 by default; =ORG_DISPATCH_SETTLE= overrides it). Headings June writes launch at once.
- =dispatch.commands= overrides the executable for each AUTO worker, such as ={"claude": "claude-auto"}=. Keys are =pi= or =claude=; values are executable names on the pane shell's PATH or absolute paths, without arguments, whitespace or shell syntax. Omitted entries use Herdr's native launcher. Install wrappers and Herdr's agent integration on each launching host; this setting does not install them or change the worker's =AGENT= identity. A Claude wrapper that selects a different =CLAUDE_CONFIG_DIR= must load Herdr's SessionStart hook there so the pane reports its real session. Closed Claude sessions under =~/.claude-NAME= resume through an executable named =claude-NAME= when one exists, so name per-account wrappers that way. The dispatcher reads the launching host's June config when it runs, so a scheduled task chooses its command and any account policy when due, not when queued.
- =dispatch.retire=, when =true=, lets each dispatcher run close the Herdr panes of DONE tasks the dispatcher launched, after the conservative checks in [[file:../org/README.org::*Retiring panes of DONE tasks][Retiring panes of DONE tasks]]. Off by default; =org-dispatch reconcile --dry-run= shows what it would close.

  A configured launcher may select an account with a different session store. Existing live sessions are reused, but closed sessions start fresh with instructions to read the whole Org task and Dialog, without native resume flags. Unconfigured workers keep native resume behavior. Startup waits up to 60 seconds for the expected worker to become ready and verifies its session before claiming and prompting. A failed or blocked configured launch puts the task on HOLD with a diagnostic pane reference instead of opening another tab each minute.

- =rhythm= is the user's day in local =HH:MM=: heartbeats run from =wake= until =quiet=, and the nightly reflection from =sleep= until =wake=.
- =reflection= runs the nightly pass once the user has been quiet for =quietMinutes=; =recentDays= is how many recent "Day's end" entries June sees in her prompt; =periods= are the longer digests that follow it. =bitcoin= (false by default) has the nightly pass fetch bitcoin's price and its day and week change from CoinGecko's free public API, with no key and a 10-second timeout, so a big move reaches her mood; a failed or slow fetch is left out and never fails the pass.
- =heartbeat= enables a private look every =everyMinutes= in waking hours; the user counts as chatting if they wrote within =chattingMinutes=.
- =looseEnds= enables June's evening look for loose ends, once a day from =at= (local =HH:MM=) until =rhythm.quiet=.
- =conflicts= enables June's nightly Syncthing check, once a day from =at= (local =HH:MM=) until =rhythm.quiet=.
- =ntfy.url=, an ntfy topic's address such as =https://ntfy.example.com/june=, pushes each finished reply meant for the phone (one answering a phone message, or a notice routed there) to that topic while the June app does not have the conversation open; a tap opens the app on it (=june://conversation=). Off without it.
- =mail= gives each heartbeat the new mail matching =query= in notmuch since the last look; =accounts= names each top-level maildir folder, such as ={"personal": "home"}=.
- =watch= tells June about dispatched tasks she did not queue on =dispatch.hosts=, in waking hours and at most every =gapMinutes=.
- =situation= feeds the =now= section: =calendars= are Org files read for today and tomorrow, =homeAssistant.people= are =person.*= entities, =homeAssistant.weather= a =weather.*= entity, polled every =pollSeconds= when =HASS_URL= and =HASS_TOKEN= are set.
- With =IMMICH_URL= and =IMMICH_API_KEY= set in her environment, June asks the user's Immich which of their named people are in each photo they send her, before she sees it (=src/immich.ts=). The key needs =asset.upload=, =asset.read=, =asset.delete=, =face.read=, and =album.read=. Immich has no scan-only call, so the photo is uploaded as an archived asset, read back once face recognition has named its faces, and deleted for good, skipping the trash; the delete runs after she has the photo. A picture with no face by 2.5 seconds, such as a screenshot, is done then, and a face still unnamed by 6 seconds counts as someone Immich does not know; 15 seconds is the cap. The scan also asks Immich's similar-image search for the photo's original in the timeline. The most similar one counts only if it was taken in the last seven days, since the search gives no score and an old photo of the same place can come first; June is then told when and where it was taken and its albums, and the input keeps =imageTaken= for the timeline. Immich is pinged at startup and every five minutes (=/api/server/ping=, no key needed), and the result is written to =immich.json= in her state directory. Photos are scanned only while the last ping answered, and a failed scan marks Immich down until the next good ping, so a photo never waits on a server that is down. Names reach her as one line beside the photo and are kept in the input's =imagePeople=, which the timeline shows. A failure leaves them out.
- =patter= sets when patter speaks: a run busy =openAfterSeconds= becomes a wait, and =gapsSeconds= are the pauses between lines, the last repeating.
