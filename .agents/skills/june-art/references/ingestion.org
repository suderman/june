** Read current code and the actual inventory entry
Implementation authorities are =art/june-art.mjs=, =art/layout.mjs=, =src/avatar.ts=, =overlay/compose.mjs= and =docs/interfaces.org= in the checkout. The full inventory is =$ART/art-list.org=. Inspect these before assuming flags or metadata are unchanged. CLI usage is printed for an unrecognized command; there is no dedicated help flag. =nix run .#art -- --help= prints usage and exits 2, not an installation failure.

Current syntax, from repository root:

#+begin_example
nix run .#art -- status SET
nix run .#art -- ingest SET NAME [--file PATH] [--face X,Y,W,H] [--mouth X,Y] [--gesture NAME,X,Y,W,H]... [--max-width PX] [--key COLOUR] [--fuzz PERCENT]
nix run .#art -- sheet SET NAME [OUT]
#+end_example

Nix provides ImageMagick and =realesrgan-ncnn-vulkan=. First realization may fetch dependencies; it is not permission to install a replacement image toolkit. Plain =node art/june-art.mjs= needs a compatible Node TypeScript loader/runtime and those binaries, so prefer the flake command.

** Sprite composition
Foreground character assets need genuine PNG/lossless-WebP alpha, sRGB, no room, floor shadow, panel tint, speech bubble or lettering. Application draws hearts, sparkles, sweat/anger/steam/emphasis marks; blush and facial tears may be drawn. Live thought-puff and snoozing-letter descriptions conflict with that rule and require coordination, not silent baking-in.

Standard source should include complete crown/hair/headset down to about waist, face looking/gesturing as specified, with clear side/top space and all needed hands/props. Raised arms need extra headroom. Approximately a third of library faces front, a third viewer-left and a third viewer-right, following each named entry. =facing:right= means toward the viewer's right edge, and =left= toward the viewer's left, not June's anatomical right/left. Do not mirror an image to conceal wrong headset/accessory construction. Metadata can allow mirroring, but approved idle uses =mirror:false=.

Actual standard normalization targets face height =0.27*2662= and face center y =0.33*2662=. Tall targets face height =0.10*4096= and center y =0.13*4096=. Face width is determined by measured source proportions. Standard side/top protection is 4%; the figure may intentionally run off the bottom for a waist cut. This conflicts with a literal four-sided margin statement in the inventory. Jon accepted current ingestion for idle; document the discrepancy without changing art direction, ingester or renderer. Since =248b2e0=, a wide silhouette grows the canvas in =WIDTH_STEP= increments, currently 128 px, up to =MAX_WIDTH=, currently 3072 px. These values come from =art/layout.mjs= and are tunable, not permanent limits. Face scale is unchanged; artwork requiring more than the limit is refused before upscaling. =--max-width= overrides the limit only with an explicit reason and authorization. Do not shrink the face or regenerate sound gestures merely to fit the old base width. A too-high crown is shifted down with a warning. A source that ends too early may float at the bottom.

** Measure source pixels, not the final canvas
Measure face cheek-to-cheek, forehead/hairline through chin, excluding hair/headset as far as anatomy permits. Record =[x,y,width,height]= on the source-size transparent image. Measure the mouth center =[x,y]= on the same image. Annotate a separate source copy with a box/dot and inspect visually. Do not copy the old face box onto a newly generated head. ImageMagick =-draw 'rectangle ...' ... -draw 'circle ...'= is enough; no automatic face detector was validated here.

Worked source =idle-attentive-s4002= is 1024x1344: =faceBox=[402,104,224,276]=, mouth =[507,321]=. Annotated evidence is =$ART/production-idle/source-face-box.png=. Feed source mouth through =--mouth 507,321=; a pixel mouth array in JSON would be interpreted as finished manifest data, not automatically transformed. If absent, code guesses center-x and 80% down the final face.

Finished =face= and =mouth= are BOTH fractions of the entire final image. Mouth is not relative to face. With source placement =(x0,y0)=, original-to-output scale =s=, canvas =(W,H)=, final mouth is =[(x0+mx*s)/W,(y0+my*s)/H]=, rounded to three decimals. Manifest validator requires mouth inside face. =readPoses= converts them to objects for =frame=/=panelLayout=; face geometry controls scale/crop/clear space, mouth controls balloon-tail target.

Approved normalized idle: size =[2048,2662]=, face =[0.358,0.195,0.285,0.270]=, mouth =[0.491,0.407]=. Its 276-pixel source face becomes about 719 pixels high. Ingest invokes 4x anime Real-ESRGAN when placement scale exceeds 1.05, then Lanczos normalization. Final resolution is not native diffusion detail.

** Read-only normalization preflight
Before accepting a gesturing source, run =examples/preflight-pose.mjs= on its already segmented RGBA image. It imports this checkout's actual =placePose= and canvas/margin constants from =art/layout.mjs=, uses the ingester's alpha-over-50% bounds and integer placement/resize rounding, and prints JSON. It does not ingest, upscale, segment, write artwork or change a manifest. Requires existing =node= and =magick= on PATH. An exit status of zero means a report was produced, not that the artwork passed review.

#+begin_src sh
node "$SKILL/examples/preflight-pose.mjs" \
  "$ART/production-gesture-pilot/sources/warm-small-wave-transparent.png" \
  --face 442,120,226,267 --gesture wave,756,232,231,269 \
  --normalized "$ART/production-gesture-pilot/processed/warm-small-wave.webp"
#+end_src

The helper calls current variable-width =placePose= and reads its default maximum and width step. =width_fit= reports the silhouette span, minimum margin-preserving width, step-rounded required canvas width and whether the actual placement accepts it. A refused placement is a JSON report with the ingester's reason, not a missing-size crash. Optional =--max-width= matches the ingester override; no proposed limit is hardcoded. Re-read current code and reported hashes before relying on older measurements. If =--normalized= points to a historical fixed-width asset, =size_matches_current_prediction=false= distinguishes its observed clipping from the current wider transform. An unchanged size is not proof of identical provenance. Anatomy, source completeness and panel checks remain separate.

Distinguish four causes:
- Source clipping: inspect original pixels and reported alpha contact at image edges. Bottom contact can be an intentional waist cut; clipped crowns or defining fingertips are genuine source defects.
- Predicted normalization loss: current transformed silhouette/gesture bounds and source-pixel centers outside the canvas. Adding blank margins does not change gesture-to-face proportions or the required width. Do not enlarge a measured face box or shrink the face to conceal overflow.
- Actual normalized clipping: inspect the saved WebP, its boundary contact, crop sheet and defining gesture. ESRGAN/Lanczos may change edge pixels, so projected source counts are not exact lost output-pixel counts.
- Panel crop/dialogue occlusion: inspect the actual desktop/narrow preview and frame/balloon geometry. A correctly ingested hand can still be hidden; neither width fit nor zero normalization loss certifies panel visibility.

Include fingertips and the visually important hand/wrist in measured gesture boxes, not an arbitrary whole-image rectangle. The implemented source schema is optional =gestureBoxes: [{name, box: [x,y,w,h], primary: true}]= in source pixels, or repeatable =--gesture NAME,X,Y,W,H= flags with the first primary. Finished =gestures= use fractions of the whole output canvas. Exactly one gesture must be primary. Ingest filters allowed framings to those that show it when any qualify; the renderer checks actual crop and dialogue visibility and can adjust framing or select a compatible fallback. None of that waives visual review. The helper's =--gesture= measures geometry only; it does not modify metadata or run the compositor.

A defining gesture cut by normalization must never silently pass production review. Width acceptance does not protect a low hand from the fixed canvas bottom. Ingest now checks every supplied source gesture before upscaling or writing an asset, rejecting empty regions or any alpha-over-127 source-pixel center projected outside the normalized canvas. Preflight uses the same =gesturePreservation= calculation and reports =source_preservation_gate.accepted= separately from =width_fit.accepted=. Source-edge contacts remain inspection flags, not an anatomy verdict. Region counts include any opaque clothing or furniture inside the measured rectangle, not semantic fingers; measure the important gesture accurately. This gate cannot certify unmeasured hands, recover already clipped source fingers, or guarantee interpolated alpha edges or panel visibility. Finished gesture boxes are clamped to the canvas; a renderer visibility score of 1 can describe only the surviving part of an already clipped source region. Compare the full source gesture with the WebP before accepting that score. Original wave 10002 needs about 2479 px and gentle palm 10302 about 2445 px including current side margins; the landed ingester rounds both to a 2560 px canvas at unchanged face scale. Before =248b2e0=, gentle's narrow-panel dialogue overlapped about 59% of its primary-hand bounding rectangle. That historical rectangle measurement is not a semantic visibility score or a validation of the new renderer. See =$ART/production-gesture-corrections/= for preserved pre-change measurements and the Claude handoff. Revalidate in a fresh staging set only when authorized; never silently replace earlier experiments or production assets.

** Sidecars and safe staging
An incoming metadata file is a flat entry plus =section= and optionally source =faceBox= and =gestureBoxes=. Minimal idle JSON example:

#+begin_example
{
  "section": "poses",
  "faceBox": [402, 104, 224, 276],
  "expression": "idle",
  "facing": "front",
  "mirror": false,
  "framings": ["close-up", "head", "bust", "waist"],
  "description": "Approved production waist-up sprite, seed 4002; not a full-body costume reference."
}
#+end_example

Other pose fields include =setting= (desk/couch/kitchen/standing, default desk), optional =activity=, =props= and application-drawn =marks=. Omit =marks= when none; an empty =marks:[]= fails the nonempty-list validator. =props:[]= is allowed. Do not include =full= framing for a standard source: =kindOf= uses that field to choose the tall canvas. Keep a =NAME.txt= sidecar with exact prompts, seeds, models/hashes, sampler/adapter settings, input identity, alpha method and approval state. PNG metadata is also retained, not replaced by prose.

Metadata precedence is incoming sidecar merged over existing/planned entry, then existing manifest, then optional =planned.json=. A new set can start with sidecar only; ingester creates minimal version-1 manifest. =status= counts finished manifest entries and optional planned catalogue, not the Org inventory. Production currently has no =planned.json=; zero planned and empty incoming do not mean the 105-piece library is finished. Count finished entries in the current manifest rather than copying an earlier task's total. Runtime reads finished manifests and merges fallback sets; it does not need a catalogue of every unproduced item.

The following writes a NEW staging set and runs image processing; use only with staging authorization. It never targets production:

#+begin_src sh
mkdir -p "$HOME/.local/share/june-art-staging"
SET=$(mktemp -d "$HOME/.local/share/june-art-staging/idle-replay.XXXXXX")
mkdir "$SET/incoming"
cp "$ART/production-idle/idle-attentive-source-alpha.png" "$SET/incoming/idle-attentive.png"
cp "$ART/production-idle/idle-attentive.txt" "$SET/incoming/idle-attentive.txt"
cp "$ART/production-references/promotion/idle-attentive.json" "$SET/incoming/idle-attentive.json"
nix run .#art -- ingest "$SET" idle-attentive --mouth 507,321
nix run .#art -- sheet "$SET" idle-attentive "$SET/idle-crop-proof.png"
nix run .#art -- status "$SET"
#+end_src

Original proof remains =$HOME/.local/share/june-art-staging/idle-attentive-v2=. Do not reuse it as scratch. Ingest validates metadata, reads alpha and places/scales, writes lossless WebP and manifest, copies source PNG bytes into =source/=, MOVES txt/json sidecars there and deletes incoming PNG unless =--file= was used. Preserve independent source archives before ingest. =--file= keeps that PNG, but still consumes matching incoming sidecars. The CLI can overwrite same-name output/source/manifest entries and is not a transactional no-clobber API. It checks alpha existence, not semantic matting quality; no ToonOut segmentation or default defringing occurs inside ingest.

Inspect the processed alpha, face/mouth box, dimensions and all allowed framing crops. Run the actual panel proof described in preview.org. Confirm no clipped hair/headset/props, no floating bottom, natural expression at actual size and no substantial alpha loss after upscaling. The crop sheet uses the same =readPoses/frame= functions as the application, not an invented preview geometry.

** Safe promotion after explicit approval
The completed promotion used approved source alpha/settings/metadata and the same source mouth. Production asset is =$AVATAR/poses/idle-attentive.webp=, with original =$AVATAR/source/idle-attentive.png= and txt/json. The production WebP is byte-identical to staging; JSON description alone records approval rather than pending review. The file operation itself needs no application restart, but that does not prove a running client reloaded its manifest.

For a new approved name, resolve destination symlinks, inspect =manifest.json=, target =poses/= path, =source/= files, =incoming/= and any planned entry. Record all existing hashes before changes. If that name exists anywhere, stop for replacement coordination rather than blindly rerun ingest. Approval of a new sprite does not authorize overwriting another one. Copy the archived source PNG and sidecars to production incoming only after review, adjust description to the actual approval, then run existing ingest with the measured coordinates. Verify unrelated hashes, staging preservation, expected manifest delta, normalized alpha, crop sheet and status afterward. Capture outputs and command results.

Record production availability separately from generation or staging dates. New pose IDs need their actual production =added= timestamp so old panels cannot select them. Before promoting an ID that already exists as an undated base placeholder, compare old panel choices through the actual shared compositor. A newly dated personal replacement can hide that old ID from historical fallback. In the verified laughter/facepalm promotion, preserving the base ID's undated availability restored forty historical pose/side choices; approval time remains in the promotion record. Do not remove timestamps from genuinely new IDs.

For image-only additions, verify daemon discovery and clients separately. Current daemon loads the manifest for selection and serves art dynamically; compare its HTTP manifest and WebP bytes before considering a restart. Desktop manifest objects load when created, so refreshing the connection alone does not reload art. Restart only the affected overlay when safe, then verify its configured checkout/art path and a private renderer proof. Current Android manifest loading is tied to composition/link initialization; reopen the conversation or app after art sync and verify on-device when available. A synced directory or successful HTTP fetch is not proof that a phone rendered the new art.

Do not re-promote idle merely to test these instructions: it already exists and is approved. Read-only checks are =sha256sum=, manifest inspection and =status=. Production changes, catalogue creation, runtime configuration and renderer fixes are separate decisions, not automatic consequences of generating art.
